# Neuro4ML CW2 — implementation and test guide

## Files
- `cw-decoding-completed.ipynb` — original template with **additional** response cells for Tasks 1–7. Original cells left in place.
- `s1_data_raw.mat` — provided dataset, copied to the name expected by the original loader.
- `cartoon.png`, `fits.png` — figure assets referred to by the original notebook.
- `single_layer_weights.pt`, `spiking_hidden_weights.pt` — trained PyTorch state dictionaries from a completed test run.
- `plots/` — selected figures generated during testing (the plots from Tasks 1–6).
- `execution.log` — latest local execution diagnostics; may include an interrupted repeated execution, not the earlier successful end-to-end test.

## Running
1. Extract all files into ONE folder; run JupyterLab / Jupyter Notebook from there.
2. Install dependencies using `python -m pip install numpy scipy matplotlib torch tqdm notebook nbclient ipykernel`.
3. Open `cw-decoding-completed.ipynb`, select your Python kernel and choose **Run All**.
4. Confirm output lines for neuron count, LIF verification, 10 non-spiking training epochs, held-out loss, 6 spiking-hidden epochs, and two models in the final comparison.
5. Graphs are automatically saved to `plots/plot_XX.png` by the added setup cell. Notebook training uses a 10-ms time step for speed; the LIF verification uses 1 ms. Change `training_dt` and model configuration if your marking specification expects a different simulation time step.

## Specific assertions/checks
- Normalisation mean should be close to (0,0), standard deviation (1,1).
- Data generator must give `x=(4,52,1000)` and `y=(4,2,1000)` when `dt=0.001,length=1,batch_size=4`.
- Task 3B must show spike counts `[0,20]` and analytic error < 1e-5.
- The training code prints both held-out test MSE and held-out zero-output baseline MSE. For a useful fit, model MSE should be lower.
- `assert parameters_are_finite(...)` guards against diverged weights and time constants.
- Full run should yield all final plots, including Task 7 distributions and firing-rate plots.

## Important limitations
- The *true spike acquisition sampling rate* is **not identifiable** from irregular spike event times alone. The notebook explicitly reports this rather than inventing a sample rate. Consult recording-system metadata / the primary paper for an externally documented acquisition rate.
- The block-based split reduces distribution-shift bias; it does not remove all temporal dependence.
- The paper's 10% peer-feedback marks require actually submitting substantive feedback; they are not generated by the notebook.
- Re-training changes parameters unless seeds / hardware and environment are consistent.
